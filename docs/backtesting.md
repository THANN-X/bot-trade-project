# Backtesting — กฎและกับดัก

## 1. Look-ahead bias

### กับดักชั้นที่ซ่อนอยู่: timestamp = เวลาเปิดแท่ง
ccxt ติดป้ายแท่งด้วย **เวลาเปิด** แท่ง `10:00` ของ timeframe 1h คือช่วง 10:00–11:00

```
ป้าย      ช่วงจริง        close รู้ค่าเมื่อไหร่
10:00  →  10:00–11:00  →  11:00
11:00  →  11:00–12:00  →  12:00
```

ถ้าเอา close ของแท่ง `10:00` ไปตัดสินใจ "ตอน 10:00" = แอบดูอนาคต 1 ชั่วโมง ทั้งที่ดูเหมือนทำตามกฎ

**กฎที่ใช้:** สัญญาณของแท่ง i คำนวณจากข้อมูลถึงแท่ง i → เข้าออเดอร์ที่ **open ของแท่ง i+1**
(open ของแท่ง `11:00` ≈ close ของแท่ง `10:00` ซึ่งเป็นเวลาที่เรารู้ข้อมูลครบจริง)

แท่งสุดท้ายที่ดึงมาจาก exchange มักยังไม่ปิด — ต้องตัดทิ้งก่อนใช้

### ทดสอบอัตโนมัติ (`tests/test_lookahead.py`)
1. คำนวณสัญญาณจากข้อมูลเต็ม
2. ตัดข้อมูลท้ายทิ้ง (ที่หลายจุด) แล้วคำนวณใหม่
3. สัญญาณในช่วงที่ซ้อนกันต้อง **เหมือนเดิมทุกจุด**

ถ้าเปลี่ยน = สัญญาณในอดีตขึ้นกับข้อมูลอนาคต = มี look-ahead
ทุกกลยุทธ์ต้องผ่าน test นี้ก่อนนับผล backtest

## 2. ค่าใช้จ่าย
| รายการ | ค่าเริ่มต้น | ที่มา |
|---|---|---|
| Fee | 0.1% ต่อข้าง | ใกล้ค่าจริงของ spot ส่วนใหญ่ |
| Slippage | 0.05% ต่อข้าง | สมมติฐานระมัดระวังสำหรับ BTC/USDT ขนาดไม้เล็ก — วัดจริงในฉาก 5 แล้วปรับ |

ค่าอยู่ใน `config/default.yaml` — อย่าเดาค่าอื่นเอง
ถ้ากลยุทธ์กำไรเฉพาะตอนค่าใช้จ่ายต่ำกว่านี้ ถือว่ายังไม่ผ่าน

## 3. การแบ่งข้อมูล
```
|────────── จูน ──────────|──── ทดสอบ ────|─── holdout ───|
  เลือกพารามิเตอร์            walk-forward     แตะครั้งเดียว
```
- **จูน:** ลองพารามิเตอร์ได้ตามใจ (ทุกรอบบันทึกลง journal)
- **ทดสอบ:** ตรวจว่าพารามิเตอร์ที่เลือกยังใช้ได้กับข้อมูลที่ไม่เคยเห็น
- **holdout:** แตะได้ **ครั้งเดียว** ตอนเลือกกลยุทธ์เสร็จแล้ว ถ้าดูแล้วกลับไปแก้ holdout ก็กลายเป็นข้อมูลจูนไปแล้ว
- สัดส่วนอยู่ใน `config/default.yaml` (`splits:`)
- ตัวเลข kill switch เลือกจากช่วงจูนเท่านั้น

### คำนวณสัญญาณจากข้อมูลเต็มก่อน แล้วค่อยตัดตามช่วง
ถ้าตัดข้อมูลเป็นช่วงก่อนแล้วค่อยคำนวณสัญญาณ ต้นทุกช่วงจะเสีย warm-up ของ indicator
และเสียจุดตัดที่เกิดคาบรอยต่อ
ลำดับที่ถูก: `generate_signals(ข้อมูลเต็ม)` → ตัดทั้งราคาและสัญญาณตามช่วง → ส่งเข้า engine
ไม่ผิดกฎ look-ahead เพราะสัญญาณใช้แค่ข้อมูลอดีตอยู่แล้ว (`test_lookahead` ยืนยัน)

### กฎที่รอยต่อระหว่างช่วง
แต่ละช่วงวัดผลแยกกัน จึงต้องไม่มีอะไรข้ามรอยต่อ:
- **ทุกช่วงเริ่มด้วยพอร์ตว่าง** (เงินสดเท่า `initial_capital` ไม่มีไม้ค้าง)
- **ยังถือไม้ตอนแท่งสุดท้ายของช่วง → ปิดที่ close ของแท่งนั้น** หักค่าธรรมเนียมและ slippage ตามปกติ
- **ไม่ใช้สัญญาณของแท่งสุดท้ายของช่วง** เพราะจะเข้าไม้ที่ open ของแท่งถัดไป ซึ่งอยู่นอกช่วงแล้ว

### พฤติกรรมที่ตั้งใจ: แบบเหตุการณ์ไม่เข้าไม้ที่ต้นช่วง ถ้าเส้นตัดกันไปก่อนแล้ว
เช่น ช่วงทดสอบเริ่มตอนที่ SMA20 อยู่เหนือ SMA50 อยู่แล้ว (ตัดขึ้นไปตั้งแต่ในช่วงจูน)
→ ไม่มีจุดตัดในช่วงนี้ → **ไม่ซื้อ** รอจุดตัดขึ้นครั้งถัดไป
นี่คือพฤติกรรมของสัญญาณแบบเหตุการณ์ ไม่ใช่บั๊ก
ถ้าเปลี่ยนเป็นแบบสถานะในฉาก 5 จุดนี้จะเปลี่ยน (ดู `docs/decisions/0002-hexagonal-at-stage-5.md`)

## 4. Journal อัตโนมัติ (`docs/journal.jsonl`)
`scripts/run_backtest.py` เขียนต่อท้ายไฟล์เองทุกครั้งที่รัน **ห้ามลบหรือแก้บรรทัดเก่า**
รอบที่ผลไม่สวยสำคัญที่สุด — ถ้าต้องจดเอง จะลืมจดรอบนั้นแน่

หนึ่งบรรทัด = หนึ่งการรัน (JSON):
```json
{
  "run_at": "2026-10-01T08:30:00Z",
  "git_commit": "a1b2c3d",
  "git_dirty": false,
  "strategy": "sma_cross",
  "params": {"fast": 20, "slow": 50},
  "data": {"symbol": "BTC/USDT", "timeframe": "1h", "start": "...", "end": "..."},
  "split": "tune",
  "costs": {"fee_pct": 0.001, "slippage_pct": 0.0005},
  "results": {"net_profit": 0, "expectancy": 0, "profit_factor": 0, "max_drawdown": 0,
              "win_rate": 0, "n_trades": 0, "max_losing_streak": 0, "worst_day_pct": 0}
}
```
- `git_dirty: true` = มีโค้ดที่ยังไม่ commit ตอนรัน → ผลนั้นย้อนกลับไปทำซ้ำไม่ได้แน่นอน
- ใช้ตรวจ: ลองไปกี่ชุดแล้ว (overfitting), แตะ holdout ไปกี่ครั้ง, cool-off ครบ 1 เดือนหรือยัง

## 5. โครง engine — แบบผสม
แยกงานเป็นสองจังหวะ แต่ละจังหวะใช้วิธีที่เหมาะกับมัน:

| จังหวะ | วิธี | ทำไม |
|---|---|---|
| 1. คำนวณสัญญาณ | pandas ทั้งตารางครั้งเดียว (`strategy.generate_signals(df)`) | indicator อย่าง SMA ไม่ขึ้นกับว่าเราถือไม้อยู่หรือเปล่า → คำนวณรวดเดียวได้ เร็วและอ่านง่าย |
| 2. เข้า/ออกไม้ | loop ทีละแท่งใน `backtest/engine.py` | ขนาดไม้, stop loss, kill switch ขึ้นกับ equity และสถานะ ณ แท่งนั้น (path-dependent) → ต้องเดินทีละแท่ง |

ตัวอย่างว่าทำไมจังหวะ 2 คำนวณทั้งตารางไม่ได้: ขนาดไม้ไม้ที่ 10 = 1% ของ equity หลังไม้ที่ 9
ซึ่งรู้ได้ก็ต่อเมื่อจำลองไม้ 1–9 เสร็จแล้ว

ข้อดีเพิ่ม: จังหวะ 1 ยังเป็นโค้ดบริสุทธิ์ → `test_lookahead` ตรวจได้ตรง ๆ
และตอนฉาก 5 loop ของจังหวะ 2 คือส่วนที่จะย้ายเข้าแกนกลาง (`docs/decisions/0002-hexagonal-at-stage-5.md`)
